# Project Instructions

## Mission

Build and maintain a ZCode plugin that gives macOS agents local Computer Use capabilities comparable to Codex Computer Use: inspect apps and windows, observe screenshots and Accessibility state, and operate the mouse and keyboard.

## Product rules

- Keep the Codex-compatible core tool names and request shapes stable.
- Do not add plugin-level app allowlists, action taxonomies, approval prompts, mandatory handoffs, or target-specific denials. ZCode Full Access mode and macOS TCC permissions are the authorization boundaries.
- Never claim that macOS TCC can be bypassed. Accessibility and Screen Recording still require a one-time user grant.
- Bind every window-scoped action to a returned window. Derive windowless desktop actions from a fresh `get_desktop_state` and pass `scope:"desktop"` without an unrelated window. Re-observe after state changes and verify visible outcomes.
- Keep all automation local. Do not send screenshots, Accessibility trees, clipboard data, or input text to a network service.
- Maintain English `README.md` and Simplified Chinese `README.zh-CN.md` together.
- Update `Memory.md` when an implementation decision, verified behavior, or remaining macOS-only gate changes.

## Completion gate

Run the contract tests, MCP stdio end-to-end test, plugin validators, and the macOS GitHub Actions job. A live GUI test additionally requires a logged-in Mac with Accessibility and Screen Recording granted.

## Repository hygiene

- Preserve unrelated user changes.
- Commit only task-related files.
- Do not edit this file unless the user explicitly asks or a stable project-level rule has changed.
